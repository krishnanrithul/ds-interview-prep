# Quick fixes: reactive Mock everywhere, tap targets, follow-up grading in Practice (doc 21)

**Date**: 2026-10-06

## Reactive Mock for all topics
`REACTIVE_TOPICS` removed from `src/lib/probe.js`; `reactiveEnabled` is now true for any question with key points (all 155). Mock setup says "The interviewer reacts to your answers, and each question is graded at the end", or that an API key enables it. Settings now says the key is used in Practice and Mock. Switched on before the planned real-run check of the stricter prompt rules (doc 18); if real runs show affirmations or weak re-asks, tighten `SYSTEM` in `probe.js`.

## Mastery map tap targets
On touch screens (`pointer: coarse`) each tile is a 44 px button with the visible 32 px tile centered inside, and the row gap is dropped so spacing comes from the hit areas. With a mouse, tiles are unchanged (28 px, 32 px from `sm`). The hover, active and focus styles moved to the inner tile via `group`. Checked: phone 390 px with touch, button 44×44, tile 32×32, no horizontal overflow; desktop button and tile 32×32.

## Follow-up replies graded in Practice
The Practice grade call now includes each follow-up (the wording asked), what it tests and the learner's reply. The tool returns a verdict per reply (good, partial, weak, none) and a one-sentence note. The key points are still judged on the main answer only, so the score stays comparable across attempts. The debrief shows the verdict under each reply: "Answered well", "Partly there", "Missed the point" or "No reply", with the note. `gradeAnswer` takes an optional `fus` list; `KeyPointsReview` takes `followUps` and `onGrade`. The cache key includes the follow-ups and replies (version bumped). The grade still runs only when the main answer has text; follow-up replies on their own aren't graded. Cost per grade goes up slightly (larger prompt, up to 1,200 output tokens), still about half a cent.

## API key from an env file (local development)
The key lives in the browser's storage for the address it was saved on, so a dev server that starts on another port (5174 instead of 5173) or a cleared site loses it, and the Anthropic Console shows a key only once.
- `getApiKey()` (`src/lib/grade.js`) now falls back to `VITE_ANTHROPIC_API_KEY` from `.env.development.local` when Settings has no key. Vite loads that file only for `npm run dev`, and the code reads it only when `import.meta.env.DEV`, so production builds don't contain it (checked: a build with the file present has no trace of the key in `dist`). The file is gitignored (`.env.*.local`). A key saved in Settings takes priority.
- Settings shows "Using the key from .env.development.local (dev server only)" when the env key is in use.
- `.env.development.local.example` shows the format.
- Not a secret store for a deployed app: anything a browser uses can be read by that browser's user. A public launch needs the hosted backend to keep a shared key server-side.
